# Quality Control of the Reads 
*** 

## Requirements 
- [LongQC](https://github.com/yfukasawa/LongQC) v.1.2.0 or later installed and accessible in your environment
- [FastQC](https://www.bioinformatics.babraham.ac.uk/projects/fastqc/) v.0.11.3 or later installed and accessible in your environment
> If you're using the LAVIS Cluster, load the programs as follows:
  ```bash
  module load anaconda3/2021.05
  module load longqc/1.2.0
  module load fastqc/0.11.3
  ```
*** 

## Instructions
> **Note:** Make sure to run all these commands from your project's main directory
### 1. Environment Setup 
Before performing quality control on the raw data, create a specific directory for this process:
```bash
mkdir Reads_QC
cd Reads_QC
```
### 2. LongQC analysis
LongQC is executed via a Python script. The link provided points to its location on the LAVIS Cluster; if you're working elsewhere, make sure to edit the path in the brackets to match the full path to `longQC.py`. You'll also need to edit the sample name in the `-s` argument, as well as the name of the fastq file containing the raw reads.
```bash
python [/cm/shared/apps/longqc/LongQC-1.2.0/longQC.py] sampleqc -x pb-hifi -s [PYM007] -p 80 -o LongQC ../Raw_Reads/[PYM007_merged_reads.fastq.gz]
```
> **Note:** You can adjust the number of processes/cores by modifying the value of the `-p` argument.
### 3. FastQC analysis
Since FastQC does not create an output directory, one will be created prior to running the analysis. Make sure to edit the name of the fastq file containing the raw reads to match yours. 
```bash
mkdir FastQC
cd FastQC
fastqc ../../Raw_Reads/[PYM007_merged_reads.fastq.gz]
```
